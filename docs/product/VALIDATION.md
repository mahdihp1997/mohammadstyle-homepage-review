## Commands and evidence

Dependency/build commands were run in their respective root/backend directories: `npm ci`, `npm run typecheck`, `npm run build`. Original regression execution uses `node scripts/mvp/b4-regression.mjs` (recursively covers B0–B4), `node scripts/product/legacy-mvp-regression.mjs --keep-for-ui`, and the existing `npm run test:ui`, `test:ui:mvp`, `test:ui:login`, `test:ui:server` with `PLAYWRIGHT_CHANNEL=chrome` and separate runner output directories. Test bodies are unchanged; copied helper routing targets dedicated test clusters rather than original databases.

New commands: `node scripts/product/auth-test.mjs`, `auth-policy-test.mjs`, `workflow-test.mjs`, `lifecycle-test.mjs`, `migration-test.mjs`, `backup-test.mjs`, `browser-product.mjs`, `transport-test.mjs`, `staging-test.mjs`, `audit-source.mjs`; `npm run check:secrets`; `git diff --check`. See package scripts for the corresponding convenience commands. `staging-test.mjs` runs against the locally built production containers, not Next dev. Both Dockerfiles, Compose provisioning/migration/startup and the backup/restore operator were actually executed. TLS QA uses only the exact temporary certificate's SPKI in a dedicated Chromium instance, without changing OS trust or disabling general certificate verification.

Diagnostic failures were retained in the owner's logs and corrected before successful runs: SQL alias/NULL-state boundaries, production Docker schema dependency, private-image packaging, temporary gateway form/redirect CSP, authenticated parallel 40001 retries, and premature screenshot waits. Early repeated-fixture category collisions, stale test sessions, missing synthetic ZIP/Chrome selection and a shared test-output risk were test setup issues; clean reruns use new tenants/isolated output. A direct legacy `npm test` attempt initially lacked its original DB and had 12/14; the same unchanged 14-test suite subsequently passed in the explicit isolated B0 harness, with all 35 SQL/Prisma checks. No original database was started/reset to make that command pass. No assertion, rate limit or allocation safety was weakened.

This is executed software validation, not a claim of publicly deployed production, live payment/SMS/cloud-S3 certification, performance/SLA certification, or owner visual acceptance. Production acceptance and approved external/provider/business configuration remain required.

Release whitespace check: additive already-executed migration files retain final blank lines to preserve their immutable checksums. `git -c core.whitespace=-blank-at-eof diff --cached --check` passes the remaining whitespace checks; ordinary diff check reports only those final blank lines.

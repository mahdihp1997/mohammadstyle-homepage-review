# Commercial precursor and exact final quote contract

## Working B3 precursor

MS_COMMERCIAL_PROPOSAL_V1 is an immutable commercial snapshot, not MS_QUOTE_CONTENT_V2. Its complete stored content includes business/branch/source/currency/unit, configurationFingerprint/IANA zone/candidate start-end/optional provider and choice, total/deposit/remaining, ordered server offering/service snapshots, winning policy version/hash/terms, and underlying/whole routing evidence. The exact returned document is persisted; SHA256(UTF8(restricted RFC8785 JCS(content))) is nonunique. No JSONB::text is used for commercial content hashing. PostgreSQL and TypeScript canonical byte/hash parity are tested with Unicode terms.

UUID identity, creator/session/actor, issuedAt/expiresAt, requestId, Idempotency-Key and workflow status stay outside content hash. Same content can produce distinct actor-owned proposal IDs with identical hashes. Authorization never looks up by global content hash. TTL is explicitly configured per branch60..3600seconds, based on DB clock and immutable metadata. Same actor/route/key/body replays original identity/content/expiry even if expired; different body under same key409. Expired idempotency records are conflicts, not silent new issuance.

If-Match is a deliberately conservative business pricing configuration revision. Every policy/routing/TTL mutation changes it. Proposal validation also regenerates server-owned prices/versions/terms and relevant branch/service/staff/membership/qualification/eligibility fingerprint. Any incompatible/current change returns QUOTE_STALE, never silently reprices. A new key requests a new explicit proposal. Old snapshots remain readable by their authenticated creator with branch permission. No capacity/acceptance/payment is created.

## Preserved V2 boundary

The approved docs/architecture/QUOTE_HASH_CONTRACT.md, quote-content.schema.json and quote-hash-vectors.json remain byte-identical. final-quote-contract.ts implements the approved exact field allowlist/decimal-string hash domain, UTC/UUID/Unicode checks and numeric array normalization; all existing hash vectors match. The old proposal JSON Schema over-escaped timestamp dots; the implementation applies its written exact UTC-millisecond semantic contract without changing any included field or expected hash. Raw HTTP duplicate keys/lone surrogates are rejected before DTO construction. Canonicalization follows [RFC8785](https://www.rfc-editor.org/rfc/rfc8785) and [PostgreSQL18 numeric types](https://www.postgresql.org/docs/18/datatype-numeric.html).

The utility is an integrity serializer for a future trusted B4 caller. It is not exposed as a public issuance endpoint and does not authenticate a client plan or prove relational snapshot/capacity validity. B4 must regenerate a server-authenticated feasible single-provider resource plan, verify all references/durations/dependencies/containment/prices/routing/snapshot equalities under transaction locks, persist the exact V2 document plus normalized quote/items/resolution/sources, and bind actor-owned exact quote ID/hash/policy snapshot/TTL and explicit consent to a booking revision. Proposal routing uses a separate evidence shape (whole override position0 plus underlying winners); B4 must construct the V2 per-item sourceAssignments and resolved-artifact snapshotHash afresh, never copy that precursor shape blindly.

No final pricing_quote, customer, booking, revision, hold, allocation, payment or acceptance FK is faked to break the architectural B3/B4 cycle. A future forward migration installs the approved dependency-closed cohort and any reviewed precursor-to-final audit reference. Keep final content integrity separate from request identity and ownership. B3 commercial evidence can assist review, but cannot substitute for a validated B4 final quote.

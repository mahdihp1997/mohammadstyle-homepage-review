# ADR-012 — Explicit server contract transition rather than mislabeled demo

Status: **PROPOSED**, pending Phase 03A review. Date: 2026-10-29.

## Context and decision

Keep current TS source unchanged. Future DTOs are authoritative plan/quote/hold records; add a reviewed adapter and explicit server source variant/minimal type widening.

## Alternatives and trade-off

DemoTimeSlot.source is demo and the reducer currently enforces it; casting real data as demo is dishonest and unsafe. ServiceId is also a six-key union, not arbitrary UUIDs.

## Consequences and revisit trigger

A future scoped integration change needs actual frontend regression QA. AvailabilityProvider shape can be reused, but cannot be truthfully claimed drop-in without those explicit changes.

No implementation or deployment is authorized by this ADR. Revisit on approved business requirements, measured load, gateway capabilities or a demonstrated invariant failure; record a superseding ADR rather than silently rewriting accepted decisions.
